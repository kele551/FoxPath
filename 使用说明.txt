狐径 FoxPath - 使用说明
作者: 海风（kele551）   https://github.com/kele551/FoxPath
版本看 exe 属性, 或控制面板标题
================================

它是什么:
  国内访问 github.com 时通时断。狐径不查 DNS, 也不改 hosts ——
  它自己拿着一批 GitHub 官方 IP 逐个实测握手, 挑当前能用的直连。
  本机代理 + PAC, 只接管 GitHub 相关域名 (主站 / raw / 发布附件 / Pages 网页)。
  不需要管理员权限, 不写 hosts, 不改系统 DNS。
  (手机流量能开、电脑宽带上不去, 多半就是本机解析到的那个 IP 不通)


1. 怎么用 (就一步)
   双击「FoxPath.exe」运行。
   - 会自动打开浏览器控制面板 http://127.0.0.1:8788/ui
   - 会自动把系统代理设成自带的 PAC, 接管这几个域名:
       github.com / www.github.com          (主站)
       raw.githubusercontent.com            (raw 文件, 例如各种一键脚本、配置文件)
       objects.githubusercontent.com        (GitHub 发布附件的下载)
       github.io / *.github.io              (GitHub Pages 网页, 例如项目自建的演示页)
     其中 raw / 附件 / Pages / avatars / camo 走【专属 IP 池】 (官方 185.199.108.0/22):
     它们同一段、同一张 *.githubusercontent.com 证书, 既不会连错服务器也不会撞证书。
     实测同一张 282KB 头像: 直连 5.7~14.2 秒, 走代理 1.1~4.7 秒 ——
     页面上有几十个头像, 它们直连被堵时主站就算秒开页面也一直转圈。
     只有 githubassets.com 仍直连 (不同域、证书不同, 实测 0.27 秒本来就快)。
   - 其他网站完全走原路线, 不受影响
   - 屏幕上看不到窗口是正常的: exe 没有控制台, 日志写在
     %LOCALAPPDATA%\FoxPath\foxpath.log
   - 首次启动请等 15 ~ 20 秒: 程序要并发体检 49 个候选 IP,
     体检完成前代理还没完全生效


2. 控制面板 (从上到下四块)

   [1] 版本与升级
       左边是当前版本, 中间一条箭头, 右边是新版本号 —— 没有新版时右边是「—」。
       - 检查更新   问一次升级源 (GitCode 优先, GitHub 兜底)
       - 立即升级   只在真有新版时才出现。点了之后的过程是:
                    下载新 exe → 校验 SHA256 → 交给一个独立小助手 →
                    旧程序退出并还原系统代理 → 覆盖 exe → 自动重启
                    下载时那条渐变进度条会走, 全程不用你手动换文件。
       升级失败会红字写明原因 (连不上升级源 / 校验不过 / 信息里没有下载地址),
       校验不过就放弃, 不会留下半成品。

       卡片里两个勾选框 (都默认开):
       - 自动升级      开着: 启动后发现有新版本会自动下好、校验、换上新版并重启,
                       全程不弹确认框; 关掉就只提示, 点「立即升级」才升级。
       - 升级结果气泡  开着: 升级成功或失败会在屏幕右下角弹一次小气泡
                       (成功「狐径已自动升级到 vX.Y.Z」; 失败一句人话 + 一句怎么办),
                       几秒后自己消失, 不用点、不打断你。
                       平时不弹 —— 已是最新版、或者根本没在升级时都不会弹。
                       关掉就完全不弹, 只看卡片里那一行状态。

       卡片最下面一行是「上次升级结果」: 成功还是失败、什么时候、失败原因是什么,
       都留在这儿, 不用靠气泡记 (程序重启后这一行还在)。

   [2] 加速状态
       出口 IP      当前在用哪个 GitHub IP, 以及延迟
       加速状态     已启用 / 未启用
       上次体检     上一轮测完候选池的时间
       - 启用加速     把系统代理指向本程序 (PAC)
       - 停用并还原   手动关掉加速, 并把系统代理恢复成原来的样子
       - 立即重测     立刻重测一批官方 IP, 不用等 5 分钟那一轮
       - 开机自启     勾上 = 写当前用户的 HKCU Run, 下次登录自动后台启动
       - 退出并还原   安全退出, 并把系统代理恢复原状 (点之前会问一次)

   [3] 当前可用 IP
       按延迟排序的可用 IP 表, 每 5 分钟自动重测刷新。
       这栏一个都没有 = 当前线路一个候选都不通, 程序会自己重拉官方 IP 表
       并回退系统 DNS。反馈问题时把这栏的数字一起贴上, 定位快很多。

   [4] 本机 git 与 SSH
       git 接管       开关, 默认开。下面一行现状告诉你: git 里 GitHub 那几条
                      代理键现在指着谁 (启用加速时指过来, 停用/退出时逐条还原;
                      你或别的工具设的代理一律不覆盖)
       SSH 通道       实测 github.com:22 与 ssh.github.com:443 的握手结果,
                      只测、不参与登录、不改任何配置
       - 重测 SSH       立刻再量一次
       - 复制 SSH 片段   把要贴的几行给你, 贴不贴、贴哪儿由你决定
                        (程序不会替你改 ~/.ssh/config)

   [5] 日志
       就是 foxpath.log 的尾部, 自动滚到最新一行。
       折起来的「更多」里还有: 本次会话搬了多少 (条数 / 字节 / 成 / 败)、
       DoH 补池最近一次结论。


3. 工作原理
   - 本机监听 127.0.0.1:8787 作为 HTTP/HTTPS 代理; 8787 被别的程序占着时
     会自动顺延到备选端口, PAC / git / 面板里写的都是实际在听的那个端口
   - 代理 github.com / www.github.com / raw.githubusercontent.com /
     objects.githubusercontent.com, 其余域名 PAC 返回 DIRECT
   - git 接管: 启用加速时把 ~/.gitconfig 里 GitHub 那几条
     http.<url>.proxy 指到本机代理, 停用/退出时逐条还原;
     清单外但值明明指着本程序端口的 GitHub 键也会跟着走, 还原时一起清掉
   - 每 5 分钟并发重测候选池, 入选条件是 TCP 443 握手 + TLS 证书校验 +
     HTTP 首包必须 2xx/3xx (429 限流也算活着 —— 说明对面确实是 GitHub)
     (有些 IP 证书是对的, 但只服务 API/CDN, 访问首页返回 400, 必须滤掉)
   - 候选池从三个源依次同步官方 IP 段: api.github.com/meta -> GitCode 上的
     meta.json (国内三网都能拉; 联通/移动拉不到官方接口时的兜底) -> GitHub raw
   - 面板上的「线路体检」把可用数量、表源、最快 IP 列成一行, 点「复制诊断信息」
     就能直接发给作者定位问题; 自动探测全都不通时, 还能「手动指定 IP」救急
   - 候选全灭时依次自救: 重拉官方表 → 查系统 DNS → 放宽超时重测;
     三步都不通才回退系统解析 (等于没装本程序, 不会更糟)
   - 候选池见底时用 DoH (阿里 dns.alidns.com / 腾讯 doh.pub) 绕开本机解析
     问一次官方地址; 问回来的地址照样要过体检才算数 (3 分钟冷却)
   - SSH 只读探测两条通道, 给可复制片段, 但不替你写 ~/.ssh/config
   - 正常退出和开机自启的静默模式都会还原系统代理; 还原备份固定在
     %LOCALAPPDATA%\FoxPath\proxy-backup.json; git 原值备份在
     %LOCALAPPDATA%\FoxPath\git-backup.json


4. 出过问题想自救
   程序被强杀、或者 exe 已经删了、但系统代理还指着 127.0.0.1:8788, 跑这一条收尾:

     FoxPath.exe --restore

   它只做一件事 —— 把本程序写进系统的 PAC 设置清掉; 不起代理、不开面板。


5. 打不开 GitHub 怎么办
   - 先看日志 %LOCALAPPDATA%\FoxPath\foxpath.log
   - 控制面板「当前可用 IP」那栏如果是空的, 说明当前线路一个候选 IP 都不通,
     程序会自动重拉官方 IP 表并回退系统 DNS (等于没装本程序)
   - 还是不行, 把「当前可用 IP」那栏的数字连同日志发到仓库 Issues


6. 卸载
   - 面板里点「退出并还原」
   - 勾了「开机自启」的, 再点一次取消 (会删掉 HKCU 注册表的 Run 项)
   - 本程序不写系统目录; 数据目录 %LOCALAPPDATA%\FoxPath\ 里只有日志和一份
     代理还原备份, 可以整个删掉
   - 最后删掉 exe 所在目录即可
   - 万一 exe 已经删掉、系统代理却还指着本程序, 用第 4 节那条 --restore 收尾


7. 版本号
   从 v1.0.3 起产物固定叫 FoxPath.exe, 文件名不带版本号;
   版本号写进 exe 属性 (鼠标悬停, 或右键 - 属性 - 详细信息), 控制面板标题上也写着。

   当前是哪个版本: 看上面那两处任意一处 (本文件不抄版本号, 免得写死了会过期)。
   各版本分别改了什么: 见仓库里的 docs/CHANGELOG.md
   (https://gitcode.com/kele551/FoxPath/blob/main/docs/CHANGELOG.md)


8. 注意: 以前随仓库提供过一个旧版脚本 (Fix-GitHub.ps1 / Run-GitHubFix.bat)
   - 那是另一套做法: 直接改系统 hosts 文件 + 装计划任务, 需要管理员权限(会弹 UAC)
   - 它与 FoxPath.exe 无关、也不会一起运行。为了与「不改 hosts、不改系统 DNS、
     不需要管理员权限」的承诺一致, 这套脚本已于 2026-10-16 从仓库移除
   - 如果你以前跑过它, 收尾办法(两步, 都需要管理员权限):
     ① 任务计划程序里删掉名为 GitHubDirectFix 的任务
     ② 打开 C:\Windows\System32\drivers\etc\hosts, 删掉
        "# >>> GitHubDirectFix BEGIN >>>" 到 "# <<< GitHubDirectFix END <<<" 之间的那段

升级时请注意：
  升级完成后程序会自动重新打开。如果它没出现（个别杀毒软件会拦住升级后的
  第一次启动，实测火绒出现过这种情况），双击一下 FoxPath.exe 就能正常使用，
  升级本身是完成的。
  为什么：新版本的文件刚落地时，杀软要做一次"首次运行"检查，可能把第一次启动拦掉。
  程序退出前已经把系统代理还原好了，所以不会影响你上网、也不会让浏览器出错。

【升级的两条保障（v1.0.7 起）】
  · 不会把旧版本当新版本：只有线上确实更新才会提示升级；线上更旧时按钮是灰的，点了也不会降级。
  · 升级失败会自动回滚：新版起不来时，程序会把旧版本放回去并重新打开，不会再出现"升级后程序没了"。
  （v1.0.6 → v1.0.7 这一跳仍可能失败一次，双击 FoxPath.exe 即可；v1.0.7 之后的升级全程带护栏。）
