## v1.2.4（2026-10-31）

狐径 FoxPath v1.2.4 — 装完新版立刻能开网页；断流 / 高丢包也压下去了

- **装完新版不再"网页打不开"**：根因是冷启动空窗——`main()` 先开代理、后台体检池从 0 填起要 1~2 分钟，期间代理已开却无可用 IP，自动升级每次都撞上。现在：
  - **持久化体检缓存**（`health_cache.json`，24h 有效、原子写）：启动即 `load_health_cache()` 恢复初始候选池，空窗消除。实测带缓存重启 `t+0s` 池即满（github 可用 24），日志 `已从体检缓存恢复初始候选池`；
  - **探测并发 12→24**：即使清缓存的首次冷启动，0→25 也只要约 16s（原 1~2 分钟）。
- **断流 / 高丢包根治**（上一轮收口）：
  - CONNECT 握手阶段透明换 IP 重试（`_TUNNEL_RETRY=3`），中途断流标记 `stalled` 续传；
  - `_rank_key` 综合 断流(+10) / 0 字节(<4KB 再 +20) / 丢包 / 吞吐 / 新鲜度 重排 IP 池；
  - 自愈退让判据由 `max(n)` 改为 `n[0]`，修掉退让从不生效的 bug；
  - 新增滚动岗哨 `_patrol_once`（探前排最陈旧）与轻量探活 `_light_retest`（失败先轻敲前排）；
  - 新增 `STALL_WATCHDOG=15.0` 静默检断流；面板新增 `good_strong_n` 验收指标（真机 24/24 通过，由 ~8 升至 29）。
- 同步 AGENTS / README / docs；新增 `tests/test_health_cache.py`、`test_boot_state.py`、`test_patrol.py` 等 7 个单测覆盖上述修复。

## v1.2.3（2026-10-26）

狐径 FoxPath v1.2.3 — 「网页打不开」的三处收口：不再押直连、断流单独记账、面板说实话

- 这一版不改网络架构，改的是**遇到全线故障时的处置顺序**和**面板上那个骗人的数字**。
- ① **候选池全灭后不再立刻撒手，也不再盲目押直连**：建连时限从写死 8 秒改成按该域名
  最近真实耗时动态放宽（上限 20 秒），全灭后先在池子里**再转两轮**（每轮先看剩余预算，
  超时就走），同时查后台的直连实测结论——**直连刚测过且不通，就不把剩下的预算押在它身上**。
- ② **半途断流与握手失败分成两本账**：以前只有"连不上"会被记失败，一个 IP 搬了 20 万字节
  就停手，下一轮照样排在最前面。现在断流单独记账（5 分钟窗口），排序即降权，
  **同一 IP 断流 2 次直接从池子请出并触发自愈**。
- ③ **面板第一格从「可用 N/50」换成「网页实测」**：读的是最近 3 分钟**真实转发**的结局
  （能打开 / 时通时断 / 能打开但常断流 / 打不开），明细里写清断流几次、502 几次、中位耗时。
  "体检可用 6/50"那种数字降成括号里的补充信息——**体检绿灯不代表网页打得开**，这一版起两者分开。
- 顺带修掉一处老 bug：转发时判断上游是不是回了 4xx/5xx 假前门，代码取的是状态码的**第三位**
  （`400`/`500` 全漏判），现在按第一位判。
- 新增回归测试 `tests/test_web_ledger.py`（不联网、不吃时钟，把上面三条各自钉住）。
