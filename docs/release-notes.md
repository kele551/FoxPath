## 这一版改了什么

这一版不改网络架构（客户端改不了，也不该由客户端硬改），改的是**出事时的处理顺序**
和**面板上那个会误导人的数字**。

### 1. 候选池全灭之后：先在池子里再转两轮，别再拿剩下的时间赌直连

- 以前：一轮并发试完没人接，就把**剩下的预算**押在「绕开代理直接连」上。而直连在国内宽带上是
  长期不通的（实测十几秒超时），这一押等于把用户最后的耐心烧在一条已知死路上。
- 现在：押直连之前先看后台的直连实测结论。**刚探过、且不通 → 不赌，直接老实报错**；
  没探过或探测结果过期 → 才按老办法试一次。
- 同时：全灭后先在候选池里**再多转两轮**（每轮起手先看剩余预算，预算不够就不拖），
  并把上一轮刚恢复的热门 IP、热备 IP 重新纳入 —— 这条链路半衰期只有几分钟，
  多争取两三秒往往就赶上池子补员完成。
- 建连时限也不再写死：按**该域名最近真实建连的中位耗时**放宽到两倍（上限 20 秒）。
  线路慢的时候固定 8 秒会把本来能成的连接判死；全灭期反过来也不会陪着傻等。

### 2. 「搬了一半就停」和「压根连不上」分成两本账

- 以前只记握手失败。一个 IP 每次搬了大量字节就断流，它在下一轮体检里照样是「可用」，
  照样排最前面 —— 用户看到的就是「时好时坏」。**这类 IP 恰恰是最该往后排的**。
- 现在：断流单独记账（5 分钟窗口），候选排序把它一起算进去（**断过一次就开始降权**）；
  **同一 IP 窗口内断流两次，直接从候选池请出**并触发自愈，下一轮体检再按实测把它捞回来。
- 不到 4KB 就断的，按「根本没开始传」处理，比半途断流更差。

### 3. 面板第一格换成「网页实测」

- 第一格从 `可用 6/50` 换成**最近 3 分钟真实转发得出的结论**：
  `能打开` / `能打开，但常断流` / `时通时断` / `打不开` / `还没实测`。
  明细里写清楚：成功几次、断流几次、502 几次、假前门几次、中位耗时多少。
- 「体检可用 N/50」没删，**降级成括号里的补充信息**（含「几个仅验证书」）——
  体检绿灯并不等于网页打得开，把这两个数字混为一谈正是此前误判的来源。
- 诊断页与「反馈包」一并带上这个结论，出问题截图一张就能分清是链路问题还是程序问题。

### 4. 顺手修掉一处老判断错误

转发时判断上游是否回了 4xx/5xx（假前门），代码取的是状态码的**第三位**，
`400` / `500` 全被漏判成正常。现在按第一位判。

## 已知边界（说明白比藏着重要）

- 运营商如果按 **SNI** 掐断（TLS 握手里能看到域名），本地代理帮不上忙 —— 只能换网络或换方案。
- GitHub 官方 IP 池在国内实测**半衰期约 5～6 分钟**，全线故障期「50 个里只剩几个可用」是常态；
  这一版能做到的是**不假装没事、不浪费用户耐心、让最容易坏的 IP 先靠边站**，
  而不是让必然坏的东西变好。
- 线路分钟级抖动期间，主站可能"通几秒、堵几十秒"，网页实测那一格会如实反映。
- 只代理 GitHub 相关域名；**不改 hosts、不改系统 DNS**，退出时还原系统设置。
- 控制面板只监听 `127.0.0.1`，接口已做 Host/Origin 同源校验；危险动作只接 POST。

## 校验与升级

- 升级源仍以 **GitCode** 为主（国内快），GitHub 兜底；
- Ed25519 公钥验签不变：**验不过 / 缺签名 / 签名格式不对，一律拒绝并保留当前版本**；
- 签名私钥只在维护者机器上，绝不进程序、绝不进仓库。
