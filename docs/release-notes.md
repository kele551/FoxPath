## 这一版改了什么

这一版解决的是两件最影响体验的事：**① 每次装新版（尤其自动升级后）"网页又打不开"**，
和 **② 断流 / 高丢包**——后者是上一轮就在收口的，这一版把收口做实。

### 1. 装完新版，网页秒开（根治"每次发新版又打不开"）

- 根因是**冷启动空窗**：`main()` 先把代理开起来，后台体检池从 0 填起要 1~2 分钟
  （现在约 16s），这期间代理已开、却一个可用 IP 都没有——网页自然打不开。
  **自动升级每次都正好撞上这个窗口**，所以"一装新版又打不开"几乎必现。
- 现在：
  - **持久化体检缓存**（`health_cache.json`，24 小时有效、原子写）：启动即 `load_health_cache()`
    把上次的初始候选池瞬间恢复回来，**空窗直接消失**。实测带缓存重启 `t+0s` 池就满了
    （github 可用 24 个），日志里会打一句 `已从体检缓存恢复初始候选池`。
  - **探测并发 12→24**：就算清掉缓存的"最冷"启动，0→25 个可用 IP 也只要约 16 秒（原来 1~2 分钟）。
- 新增回归测试 `tests/test_health_cache.py`（不联网、不占端口，4 条异常路径 + 往返校验都钉死）。

### 2. 断流 / 高丢包的根治（上一轮收口做实）

- CONNECT 握手阶段**透明换 IP 重试**（`_TUNNEL_RETRY=3`），中途断流标记 `stalled` 续传；
- `_rank_key` 综合 **断流(+10) / 0 字节(<4KB 再 +20) / 丢包 / 吞吐 / 新鲜度** 重排 IP 池，
  最该靠后的先靠后；
- **自愈退让判据修 bug**：由 `max(n)` 改成 `n[0]`，原来退让条件永远不触发，等于没退让；
- 新增**滚动岗哨** `_patrol_once`（探前排里最陈旧的）与**轻量探活** `_light_retest`（失败先轻敲前排）；
- 新增 `STALL_WATCHDOG=15.0` 静默检测断流；面板新增 `good_strong_n` 验收指标——
  **真机 24/24 通过，由 ~8 升到 29**。
- 同步补了 `tests/test_patrol.py` 等 7 个单测覆盖上面这些修复。

## 已知边界（说明白比藏着重要）

- 新增的 `health_cache.json` 只是本机缓存：过期（24h）或文件损坏会自动忽略、走正常冷启动，
  不影响安全；它不记录任何隐私，退出不删（下次冷启动接着用）。
- 运营商如果按 **SNI** 掐断（TLS 握手里能看到域名），本地代理帮不上忙 —— 只能换网络或换方案。
- GitHub 官方 IP 池在国内实测**半衰期约 5～6 分钟**，全线故障期"50 个里只剩几个可用"是常态；
  这一版能做到的是**不假装没事、不让最容易坏的 IP 排前面、让升级后不再有空窗**，
  而不是让必然坏的东西变好。
- 只代理 GitHub 相关域名；**不改 hosts、不改系统 DNS**，退出时还原系统设置。
- 控制面板只监听 `127.0.0.1`，接口已做 Host/Origin 同源校验；危险动作只接 POST。

## 校验与升级

- 升级源仍以 **GitCode** 为主（国内快），GitHub 兜底；
- Ed25519 公钥验签不变：**验不过 / 缺签名 / 签名格式不对，一律拒绝并保留当前版本**；
- 签名私钥只在维护者机器上，绝不进程序、绝不进仓库。
