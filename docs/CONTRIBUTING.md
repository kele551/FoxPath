# 参与贡献（Contributing）

> 狐径 FoxPath —— 作者：**海风（kele551）** · <https://github.com/kele551/FoxPath>

先说清楚这个项目的脾气，能省掉双方很多时间：

- **它只有一个目标：让这台机器上的 GitHub 能正常打开。** 不做全局加速、不接管其它域名、
  不经过任何第三方服务器 —— 原理就是"拿着 GitHub 官方 IP 逐个实测握手，挑当前线路能用的直连"。
- **零第三方依赖是底线。** 主程序全部 `import` 都是 Python 标准库。想合入一个需要 `pip install` 的依赖，
  基本会被拒。
- **版本号只给新功能用。** 修 bug 的改动攒到下一个功能版一起发。你的 PR 合了不等于马上发版。
- **改注册表的地方要格外小心。** 这个程序会写 `HKCU\...\Internet Settings`（系统代理/PAC），
  所有相关改动都必须验证"退出后能原样还原"。

## 〇、最短路径：提交一个改动（三步走）

> 这条链就是"做完"的定义：**认领 → 改并自证 → 提交时贴出验收输出**。
> 维护者侧怎么复核见 [REVIEWING.md](REVIEWING.md)。

1. **认领**：在 [TASKS.md](../TASKS.md) 里挑一条（每行都带 issue 号与**验收命令**），或先开 Issue 说清方案；
2. **改 + 自证**：一次只做一件事；改完**必须真的跑**：

   ```powershell
   python -m py_compile github_direct.py      # 语法
   python github_direct.py                    # 真跑一次（会改系统代理）
   python github_direct.py --restore          # 退出/还原链路要能走通
   python tools/preflight_release.py          # 行为类改动尽量全绿
   ```

3. **提交**：中文提交信息（`fix:` / `feat:` / `docs:` / `chore:`），并在 PR / Issue 里**贴出上面命令的输出** ——
   涉及注册表/系统代理的改动，还要贴出**"启用 → 退出 → 已还原"的前后对比**；写"应该没问题"的会被要求补验证。

**不需要任何令牌或私有凭据**：自检里需要凭据的检查会自动 `[SKIP]` 并打印原因，别人克隆下来就能跑。
用 AI 助手一起改也可以：先让它读 [../AGENTS.md](../AGENTS.md)（禁区清单）与 [ARCHITECTURE.md](ARCHITECTURE.md)（结构）。

## 一、怎么提 Issue

走 [Issues](https://github.com/kele551/FoxPath/issues)，有两个模板：

| 模板 | 什么时候用 | 会问你什么 |
|---|---|---|
| 🐞 报告问题 | 打不开 GitHub、体检全灭、系统代理没还原、面板异常 | 程序版本号、Windows 版本、**宽带运营商**、复现步骤、面板上"当前可用 IP"的数字、`foxpath.log` |
| 💡 提功能建议 | 想要某个功能 / 觉得现在别扭 | 使用场景、期望效果、试过的替代做法 |

**宽带运营商那一栏很关键**：联通 / 移动 / 电信 / 校园网的表现差很多，缺了这一项基本没法定位。

**提之前先做三件事：**

1. 看 README 的[已知边界](https://github.com/kele551/FoxPath#已知边界)一节 —— 哪些域名不走代理、
   被强杀后系统代理可能还指着本程序、端口占用会弹错误框，都写在那里；
2. 看 README 末尾的「路线图（Roadmap）」，已经排进计划的不用重复提；
3. 准备日志：`%LOCALAPPDATA%\FoxPath\foxpath.log` 的末尾几十行（面板的「日志」区块也能看到尾部）。

**安全问题不要开公开 Issue**，请按 [SECURITY.md](SECURITY.md) 私下报告。

## 二、PR 流程

1. **先开 Issue 对齐，再动手写代码。** 涉及候选池、注册表还原、升级链路的改动尤其要先说 ——
   这几处历史上都真出过事（见 README「版本记录」）。
2. Fork → 开分支（建议 `fix/xxx`、`feat/xxx`、`docs/xxx`）→ 改 → 自测 → 提 PR。
3. PR 描述请用仓库自带的 [模板](../.github/PULL_REQUEST_TEMPLATE.md)：**改了什么 / 怎么验证的 / 自查清单**。
   "怎么验证的"那一栏必须写你实际跑过的命令和看到的结果。
4. 维护者会**在 7 天内**给第一次答复。

## 三、代码风格

### 通用

- **中文注释、中文提交信息。** 注释写清"为什么这么做"，尤其是历史坑（这个仓库里很多行注释就是踩坑记录，别删）。
- **不引入第三方依赖。** `github_direct.py` 只用标准库；打包只额外需要 `pyinstaller`。
- **改动要能对得上文档。** 改了行为就顺手改 README / 《使用说明》里对应的话。
- **对外文案有敏感词清单**：凡涉及"网络访问限制"的说法一律不得出现在仓库任何文件里；
  具体清单见工作区章程，**不要在仓库内逐词列举**，避免清单自身被内容扫描命中
  （README、简介、发布说明、注释、Issue/PR 模板都算）—— 仓库曾因措辞被判内容违规，整页打不开。
  这七个词**连列举都不写进仓库**（写在这里就等于命中，本文件因此不再抄词表；维护者手上另存一份）。
  换成中性技术表述：**「不依赖域名解析」「本地网络分流」「连接优化」「DNS 解析异常」**。
  改完对外文案后，按维护者手上的词表搜一遍再提交。
- **不要在对外文档里写私人邮箱、令牌、口令。** 反馈入口一律用 Issues 链接。

### Python（`github_direct.py` 等）

- 缩进 4 空格；保持 `# -*- coding: utf-8 -*-` 头。
- 保命路径（退出还原、`atexit`、`--restore`）里**不要抛出异常**，吞掉异常要写日志说明。
- `.ps1`（升级小助手等内嵌脚本）**必须是 UTF-8 带 BOM**。

### 行尾与编码（这条最容易踩）

- 仓库文本文件一律 **LF**（`.gitattributes` 固定 `* text=auto eol=lf`，2026-10-16 归一）。**不要整文件重写行尾** —— 会产生"整个文件都变了"的假 diff。
  这条同时保证 **Gitee / GitHub / AtomGit 三个平台逐字节一致**：早期 GitHub 侧是用纯 REST 工具按磁盘原始字节推的，曾因此出现"GitHub 是 CRLF、另两平台是 LF"的字节差异。
- 提交前 `git diff --stat` 扫一眼：只改了几行的文件显示几百行变动，八成是行尾被改了。

## 四、如何在本地构建与自查

### 构建

```bash
pip install pyinstaller

python build_exe.py        # 产出 FoxPath.exe（版本号取自 github_direct.py 的 APP_VERSION）
```

> 以前仓库里有过 `create_icon*.py` / `make_icon_from_user_image.py` 这类做图标的一次性脚本，
> 因为把输入输出路径写在作者本机、**在别的机器上跑不通**，**已于 v1.0.8 从仓库移除**
> （原因见 [COMPLIANCE.md](COMPLIANCE.md)：图标为自绘，不该留会引入第三方素材的脚本）；
> 正常构建不需要它们，`app.ico` 已经入库。

### 自查（改完自己先过一遍）

```bash
python -m py_compile github_direct.py build_exe.py make_version_json.py tools/publish.py
```

### 测试程序时必须验证的三件事

改动涉及系统代理时，实测一遍这三条再提 PR：

1. **启用 → 退出 → 系统代理确实还原**成运行前的样子（`HKCU\CurrentVersion\Internet Settings` 下的
   `AutoConfigURL` 等值）；
2. **重复启用不会污染还原备份**（连点两次「启用加速」，退出仍能还原）；
3. **备份写不进去时不去改注册表**（宁可不开，也不留下无法还原的状态）。

⚠ 不要用 `nohup ... &` 在 shell 里后台启动来测试：命令结束时进程会被终止，测出来的现象是假的。

## 五、提交信息规范

用 [Conventional Commits](https://www.conventionalcommits.org/) 的前缀，正文写中文：

```
fix: 升级源缺少 sha256 时拒绝升级，不再直接放行

原因：原来写的是 if want and sha != want，want 为空时整个判断短路，
     等于把未校验的 exe 装到用户机器上。
改法：want 为空直接判失败并记日志（phase=failed, error=nosha）。
验证：把本地 version.json 的 sha256 改成空串，程序拒绝升级并保留旧版。
```

常用前缀：`fix:`（修缺陷）、`feat:`（新功能）、`docs:`（只改文档）、`chore:`（构建/杂务）、`release:`（发版）。

## 八、发版前自检（发布闸门，2026-10-14 自 README 迁入）

**发版前自检脚本随仓库提供，位置 `tools/preflight_release.py`**（同目录的 `tools/compare_ips.py`
用于对照官方 `meta` 网段排查候选 IP）：

```bash
python tools/preflight_release.py              # 默认拿仓库根目录的 FoxPath.exe 当候选
python tools/preflight_release.py --help       # 看全部开关
python tools/preflight_release.py --dry-run    # 只跑静态项：不写注册表、不拉程序、不碰系统代理
```

检查内容：

| 类别 | 检查什么 |
| --- | --- |
| 版本一致性 | exe 文件版本 = 源码 `APP_VERSION` = `version.json` 版本，且 `version.json` 的 `sha256` / `size` 与候选 exe 对上 |
| 冷启动演练 | 把候选 exe 复制成「刚下载落地」的样子，立刻用隐藏 PowerShell 启动，必须在限定时间内起来 |
| 完整升级演练 | 旧版 → 本地升级源 → 检查更新 → 立即升级 → 必须自己起来（起不来则必须「重试过 + 明确提示用户」），并核对换上去的文件**指纹**等于候选 |
| 失败分支 | 升级源里的 `sha256` 故意写错 → 必须拒绝并保留旧版 |
| 接口与还原 | `/pac` 纯 ASCII、`/api/diag` 正常、非法 IP 被拒、连点两次启用不污染系统代理备份、退出后注册表还原、不留垃圾 |
| 一致性警告（WARN） | ① 工作区副本与仓库副本 `tools/preflight_release.py` 的 **sha256 是否一致**（两份漂移了就警告）；② **两平台发行版附件 SHA256 是否一致**（Gitee 请求间隔 ≥3 秒限速；网络或平台异常只警告，不判红） |

> 自检会真的改注册表、拉起本机已装的狐径（结束时再把它重新启动），所以**别在有正式发布任务之外随手整轮跑**；
> 只想确认脚本自己没坏，用 `--dry-run`（只做静态检查）。
> 警告级（WARN）不阻断发布，但会在结尾单独列出来，发布前应当看一眼。
> `tools/publish.py release` 已内置这道闸门：自检不全绿直接中止发布（`--skip-preflight` 只留给线上事故回滚，且要在 `logs\` 写明原因）。

## 九、控制面板与升级细节（自 README 迁入，2026-10-15）

控制面板 `http://127.0.0.1:8788/ui`，从上到下四块：

| 区块 | 显示什么 | 能做什么 |
|---|---|---|
| **版本与升级** | 当前版本 `=====>` 新版本（没有新版时右边是 `—`）；最下面一行是 **上次升级结果**（成功/失败 + 时间 + 失败原因） | `检查更新` 问一次升级源；真有新版才出现 `立即升级`。点了以后自动下载 → 校验 SHA256 → 覆盖 exe → 重启，下面一条渐变色进度条跟着走。卡片里另有 `自动升级`、`升级结果气泡` 两个勾选框（**都默认开**） |
| **加速状态** | 出口 IP（含延迟）、加速状态（已启用 / 未启用）、上次体检时间 | `启用加速`、`停用并还原`、`立即重测`、`退出并还原`，以及 `开机自启` 勾选框 |
| **当前可用 IP** | 按延迟排序的可用 IP 表，每 5 分钟自动刷新 | 看当前线路还剩几个能用。一个都没有时会自动重拉官方 IP 表并回退系统 DNS —— 反馈问题时把这栏的数字一起贴上 |
| **日志** | `foxpath.log` 的尾部，自动滚到最新 | 打不开 GitHub 先看这里 |

> 从 v1.0.3 起文件名不再带版本号（固定 FoxPath.exe），**版本号写进 exe 的属性里**（鼠标悬停或右键-属性-详细信息可见）。
> 下载文件名故意用 ASCII（`FoxPath.exe`）。GitHub / Gitee 上传附件时会把中文
> 文件名改坏（实测 `狐径-v1.0.0.exe` 传上去变成了 `-v1.0.0.exe`），所以对外一律用 ASCII 名。

### 「升级时请注意」完整版

- **升级不用手动换文件**：新版下完先校验 SHA256，通过后交给一个小助手 ——
  让旧程序退出并还原系统代理 → 覆盖 exe → 自动重启。校验不过就放弃，不会留半成品。
- **不会把「降级」当「升级」**：升级前按版本号语义比较（`1.0.10 > 1.0.9` 这种也算得对），
  只有线上确实比本地新才会提示「发现新版本」；线上不比本地新时，面板直接说明是
  「已是最新版」还是「本地版本比线上新（线上尚未发布）」，**「立即升级」按钮置灰，
  服务端也会拒绝执行**，日志里写一行「拒绝降级」。
- **升级失败会自动回滚**：新版连续起不来时，小助手会把旧版本放回去并重新启动它，
  日志里能看到三步（覆盖失败 / 回滚 / 旧版已起来），**不会再出现「升级之后程序没了」**。
- 升级完成后程序会**自动重新打开**；万一它没有出现，**双击一下 `FoxPath.exe` 就能正常使用**
  —— 升级本身是完成的。程序退出前已经还原好系统代理，**不会影响上网，也不会让浏览器出错**。
- **历史说明更正（2026-10-09）**：v1.0.7 之前，这类「升级后起不来」曾被归因为杀毒软件拦截
  （火绒实测）。真因已查清：升级小助手是从主程序里起的，会继承单文件 exe 的 `_PYI_*` 环境变量，
  新版本的引导程序据此误判「已经解过包」，于是去找那个已被删掉的临时目录，
  结果 `Failed to load Python DLL`。**该问题自 v1.0.7 起修复**（起新版本前先擦掉这些变量）。
- **从 v1.0.6 升到 v1.0.7 这一跳**用的仍是老版小助手（不重试、不回滚），所以**仍可能失败一次**；
  失败了双击 `FoxPath.exe` 即可。**从 v1.0.7 往后，升级全程带护栏。**
- **升级源不通时怎么办（2026-10-12 补）**：如果点「检查更新」长时间显示「连不上升级源」或
  「联网失败，显示的是上次检查的结果」（Gitee/GitHub 两个 raw 源都够不着的极端线路），
  不必干等——直接到 [Gitee 发行页](https://gitee.com/kele551/FoxPath/releases) 手动下载最新的
  `FoxPath.exe`，**关掉旧程序后双击覆盖**即可，配置全部保留、无需卸载重装。

## 十、已知边界（完整版，自 README 迁入，2026-10-15）

- 代理 `github.com` / `www.github.com`，以及 **`raw.githubusercontent.com` /
  `objects.githubusercontent.com`**（raw 文件与发布附件下载，v1.0.6 起）。
  后两个走**专属 IP 池**（官方 `185.199.108.0/22`）：以前不代理它们，是因为塞进 `github.com`
  的池子会连到错误服务器、页面脚本全废 —— 那是池子不对，不是「不能代理」。
- **`avatars.githubusercontent.com` / `camo.githubusercontent.com` 也走代理**（2026-10-11 起）：
  它们与 raw/objects 同在 `185.199.108.0/22`、用的是同一张 `*.githubusercontent.com` 证书，
  共用 raw 池既不会连错服务器也不会撞证书。改它的原因：本机实测同一张 282KB 头像，
  直连 5.7~14.2 秒、走代理 1.1~4.7 秒 —— 页面上有几十个头像，它们直连被堵时，
  主站 HTML 就算秒开，页面也一直转圈。
- **仍然直连**：`githubassets.com`（不同域、证书不同，实测 0.27 秒本来就快）与 `api.github.com`。
- 不代理 `api.github.com`（本来就通），Git 命令行操作不受影响。
- 绿色单文件，无需安装；但**不能**用 `nohup ... &` 在 shell 里后台启动，那样命令结束进程会被终止。要常驻就双击运行或开开机自启。
- 如果程序被**强制结束**（任务管理器结束进程、关机时强杀），`atexit` 不会执行，系统代理可能仍指向本程序。
  下次启动本程序会自动接管；如果不再用了，跑一次 `--restore` 即可收干净。
- 控制面板只监听 `127.0.0.1`，不对局域网开放；接口已做 Host/Origin 同源校验（挡网页 CSRF 与 DNS rebinding），
  但没有做用户鉴权 —— 本机上以你的身份运行的程序仍然可以调用它。
- **如果你原本设了「静态代理」（Internet 选项里手动填的代理服务器）**：一旦启用本程序，PAC 会优先于静态代理，
  而你手动设的那个代理在启用期间不再生效（其它网站会直连）。停用/退出时会自动还原。程序检测到这种情况会在
  日志里明确写一行提醒。
- 遇到端口被占用、启动失败等情况，exe 会弹一个错误框并写明日志位置，不再"点了没反应"。
- **两个平台发行版的附件个数可能不一样**：Gitee 侧比 GitHub 侧多一个中文名演示视频
  （`演示视频-狐径.mp4`），GitHub 侧只有 ASCII 名的 `FoxPath-demo-v1.0.7.mp4` —— 这是**已知差异**
  （中文文件名在部分平台下载下来会乱码，所以对外链接一律给 ASCII 名）。
  两个核心附件 `FoxPath.exe` / `version.json` 两平台逐字节一致；每次发布都会把附件下载回来比对 SHA256。
